# DARUMA — スマホ用 PWA

スマホで要約を**読む**ための PWA。加えて、スマホから**その場で要約する**こともできる。

```
読む: 拡張機能(PC) → Drive デスクトップ版の同期フォルダ → Drive クラウド
        → この PWA が Drive API で daruma-index.json と月ごとのファイルを読む → 端末にキャッシュ

作る: YouTube アプリの「共有」→ この PWA → Gemini に動画URLを直接渡す
        → 結果は端末内（IndexedDB）に置く
```

PC の拡張機能（v0.13.0〜）は要約を「要約した月」ごとのファイルに分けて書く。
PWA は目次（`daruma-index.json`）を見て、**指紋（md5）が変わった月のファイルだけ**を落とし、
月ごとに端末へ覚える。1件増えても落とすのは今月分（数 MB）だけで済む。
目次が無ければ（PC が v0.12.0 まで）、全件入りの `daruma-archive.json` を読む。

**サーバーを持たない。** このリポジトリにあるのは静的ファイルだけで、要約データは
各自の Drive から直接ブラウザに入る。どこかのサーバーに保存されることはない。
このリポジトリが公開されていても、要約データが他人に見えることはない。

## スマホから要約する

### なぜ拡張機能ではないのか

「スマホのブラウザに拡張機能を入れれば PC と同じことができる」とは**ならない**。

- **PWA と拡張機能は別の仕組み**で、PWA に拡張機能を組み込む接続点は存在しない
- Chrome for Android は拡張機能に非対応。Kiwi Browser（Chromium系の定番だった）は開発終了。
  Firefox for Android は対応するが、Safari (iOS) は Xcode でのアプリ化と Apple Developer Program が要る
- **仮に拡張機能が動いても解決しない。** PC 版がローカルヘルパーを必要としている理由は UI ではなく
  「ブラウザ内から字幕が取れない」ことで、スマホには代わりに動かせる yt-dlp が無い

Android の **Web Share Target** を使えば、インストール済み PWA を YouTube アプリの
共有シートに出せる。拡張機能を経由せずに済み、スマホの操作としてもこちらが自然。

### 仕組み

字幕を介さず、**YouTube の URL を Gemini に直接渡して動画そのものを読ませる**
（PC 版の video-native フォールバックと同じ方式）。

- 利点: ヘルパーもサーバも要らず、端末とネットだけで完結する
- 欠点: 字幕方式より桁違いにトークンを使い、長尺動画ほど高価で遅い

Gemini API がブラウザから直接叩けること（CORS 許可）は実測で確認済み。
無効なキーで叩いて 400 の本文が JS から読めた ＝ CORS が通っている
（塞がれていればネットワークエラーになり本文すら読めない）。したがってバックエンドは不要。

### 使い方

1. 設定画面で **Gemini API キー**を登録する（キーは端末内にのみ保存され、Gemini 以外へは送られない）
2. YouTube アプリで動画を開き、**共有 → DARUMA**
   - 共有先に出てこないときは、PWA をホーム画面にインストールする
3. 一覧上部の入力欄に URL を貼っても同じ（共有が使えない場面の逃げ道）

### PC に頼む・どこで要約するかを選ぶ（2026-11〜）

共有シートや URL 欄から来た動画は、まず選ぶ画面を出す:

- **PC に頼む** … `daruma-mobile.json` の `requests` に書いて Drive に上げる。PC の拡張機能（v0.20.0〜）が
  2 分おきにそれを見て、字幕で要約する。出来た要約はいつもの取り込みで届く。頼んでいる間は、画面を
  開いていれば 1 分おきに Drive を見に行く。できなかった理由（字幕が無い等）は PC が
  `daruma-index.json` の `requests` に書くので、一覧の上の「PC に頼んだ動画」に出る
- **スマホで今すぐ要約** … これまでどおり Gemini に動画を直接読ませる

「次からは聞かずにこれにする」か設定の「共有・URL から来たとき」で、いつも片方にできる。
もう要約がある動画は、要約し直さずにそれを開く。

### 利用料を抑える（動画の読み方）

動画を直接読ませると、映像のコマが入力の大半を占める（低解像度で 1 コマ約 66 トークン、音声は 1 秒約 32 トークン）。
設定の「動画の読み方」が **少なめ**（既定）なら `videoMetadata.fps = 0.2`（5 秒に 1 コマ）を付け、
入力をおよそ半分にする。画面の文字や図が大事な動画は **標準**（1 秒に 1 コマ）に。
要約のあと、読んだ量（トークン）を要約の上に出す。

### スマホでノートを作る

要約の文字を選ぶと、画面の下に「ノートに追加」「メモ付きで」が出る。ノートは端末に置き、
`daruma-mobile.json` の `notes` で PC に送る。PC が取り込んで `daruma-notes.json` に載ったら、
端末の分は消す（それまではノート画面に「スマホ・PC へ送信待ち」と出る）。

### 縦を詰めた画面（2026-11、Galaxy Z Fold 向け）

Fold を開くと縦が短いので、上の操作は 2 段（題字とボタン・検索と期間）だけにした。
URL を貼って要約する欄はふだん畳み、ヘッダーの 🔗 で開く（主な入口は共有シート）。
チャンネルの絞り込みは外した（チャンネル名は検索欄で探せる）。要約の画面は、大きなサムネイルをやめて
小さな絵の横に題名を置き、2ペインのときは詳細の見出し帯も出さない。

### 要約を削除する

要約の画面の「削除」で消せる。この端末から消し、`daruma-mobile.json` の `deletes` で PC に伝える。
PC の拡張機能（v0.21.0〜）が当てて同期すると、Drive の要約ファイルからも消え、`daruma-index.json` の
`deleted` に載る。載ったら、こちらの控えは外す。PC で消したものも `deleted` を見て一覧から外す。

### 端末で作った要約の扱い

Drive から取り込んだ分（`driveItems`）と端末で作った分（`mobileItems`）は
**別々に保持し、表示のときだけ統合**している。混ぜて1つにすると、Drive を
取り込み直したときに端末側の要約が消えるため。設定の「取り込んだ要約を消す」も
Drive 由来の分だけを消す。

### PC への書き戻し

端末で作った要約は **`daruma-mobile.json`** として Drive に上げる。
PC が書く要約ファイル（`daruma-index.json` と `daruma-YYYY-MM.json`）とはファイルを分けてある。
**1つのファイルには書き手を1人だけ**にしておけば、両側から書いて壊し合うことがない。

```
スマホ: daruma-mobile.json  を書く（PC は読むだけ）。要約・PC への頼みごと・ノート
PC:     daruma-index.json・daruma-YYYY-MM.json を書く（スマホは読むだけ）
```

置き場所は `daruma-index.json` と同じフォルダにする。そこは PC の Drive
デスクトップ版が同期しているフォルダなので、上げれば PC のローカルにも降りてくる。
拡張機能はそれをローカルファイルとして読むので、**拡張機能側に OAuth を足さずに済む**。

PC 側が取り込むのは「そこに無い」か「あちらが新しい」ものだけ。
PC で深掘り済みの要約を、スマホの簡易要約で上書きしない。取り込みは
アーカイブ画面を開いたときと、サイドパネルの「同期」を押したときに走る。

権限は `drive.readonly` に **`drive.file`**（このアプリが作ったファイルだけを扱える）
を足している。Drive 全体への書き込み権限は要らない。
**スコープを増やしたので、既存ユーザーは一度「Google と連携する」を押し直す必要がある。**

## なぜ PWA なのか

Google Drive は **HTML をプレビュー形式としてサポートしていない**。
Drive アプリで HTML を開こうとしても毎回「ダウンロード → ブラウザで開く」が必要で、
Chrome が選択肢に出ないこともある。日常使いに耐えないので、独立した PWA にしている。

## セットアップ

### 1. Google Cloud で OAuth クライアントを作る

1. [Google Cloud Console](https://console.cloud.google.com/) でプロジェクトを作る
2. 「API とサービス」→「ライブラリ」で **Google Drive API** を有効化
3. 「OAuth 同意画面」を設定
   - User Type: **外部** / 公開ステータス: **テスト**のまま
   - **テストユーザーに自分の Google アカウントを追加する**（忘れると認証が通らない）
4. 「認証情報」→「OAuth クライアント ID」→ 種類: **ウェブ アプリケーション**
5. **承認済みの JavaScript 生成元**に、PWA を置くサイトの**オリジンだけ**を登録する

   ```
   https://<ユーザー名>.github.io
   ```

   > ここはよく間違える箇所。**パスを含めてはいけない。**
   > `https://<ユーザー名>.github.io/DARUMA/` のように書くと登録できない。

6. 発行された**クライアント ID** を控える

> **「確認されていないアプリ」の警告について**
> 使用するスコープ `drive.readonly` は Google の制限付きスコープなので、
> テストモードでは初回に警告画面が出る。「詳細」→「（アプリ名）に移動」で進めれば使える。
> 個人利用なら審査を通す必要はない。

### 2. GitHub Pages で公開する

リポジトリの Settings → Pages → Source を **Deploy from a branch**、
ブランチを **main / (root)** にする。数分で下記が有効になる。

```
https://<ユーザー名>.github.io/DARUMA/
```

> GitHub Pages を無料で使うにはリポジトリが Public である必要がある。
> 公開されるのはコードだけで、要約データは含まれない。

Cloudflare Pages を使う場合は、このディレクトリを指定して `npx wrangler pages deploy .` でもよい。

### 3. スマホで開いて設定する

1. スマホの Chrome で PWA の URL を開く
2. 右上の ⚙ から**クライアント ID** を貼り付けて「保存」
3. 「Google と連携する」→ 同意（初回は上記の警告画面が出る）
4. 取り込みが終わったら、Chrome のメニューから**「ホーム画面に追加」**

以後はホーム画面のダルマから 1 タップで開ける。一度取り込めば**オフラインでも読める**。

## 使い方

| 操作 | 動作 |
|---|---|
| 検索 | タイトル・チャンネル・本文を全文検索（「ドンキ」で「ドン・キホーテ」に当たる） |
| チャンネルのチップ | 絞り込み |
| 項目をタップ | 詳細を開く。Android の戻るジェスチャで一覧へ戻る |
| `[m:ss]` をタップ | YouTube アプリがその時刻から開く |
| 📝 | ノート（PC でハイライトした箇所とメモ）を読む |
| ⟳ | Drive から取り込み直す |

ノートは PC の拡張機能で作る。ここでは読むだけ（要約と同じ役割分担）。

## 更新したときの注意

service worker がアプリシェルをキャッシュしているため、**デプロイ直後の 1 回目は古い画面が出る**。
裏で新しいものを取得しているので、**次に開いたときから新しくなる**。
すぐ反映したい場合は設定から「端末のキャッシュを消す」か、`sw.js` の `CACHE` の版番号を上げる。

## 構成

```
index.html            一覧 / 詳細 / 設定の3画面
app.js                OAuth・Drive取得・描画・IndexedDBキャッシュ
styles.css            スマホ優先。大画面では読み幅を制限
sw.js                 アプリシェルのみキャッシュ（認証とAPIは素通し）
manifest.webmanifest
icons/
```

要約を作る側（Chrome 拡張機能とローカルヘルパー）は別リポジトリ。
