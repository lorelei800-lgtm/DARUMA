# DARUMA — スマホ用アーカイブ閲覧 PWA

PC の Chrome 拡張機能が Google Drive に書き出した YouTube 要約を、
スマホのホーム画面から読むための PWA。

```
拡張機能(PC) → Drive デスクトップ版の同期フォルダ → Drive クラウド
    → この PWA が Drive API で daruma-archive.json を読む → 端末にキャッシュ
```

**サーバーを持たない。** このリポジトリにあるのは静的ファイルだけで、要約データは
各自の Drive から直接ブラウザに入る。どこかのサーバーに保存されることはない。
このリポジトリが公開されていても、要約データが他人に見えることはない。

## なぜ PWA なのか

Google Drive は **HTML をプレビュー形式としてサポートしていない**。
Drive アプリで HTML を開こうとしても毎回「ダウンロード → ブラウザで開く」が必要で、
Chrome が選択肢に出ないこともある。日常使いに耐えないので、独立した PWA にしている。

## セットアップ

### 1. Google Cloud で OAuth クライアントを作る

1. [Google Cloud Console](https://console.cloud.google.com/) でプロジェクトを作る
2. 「API とサービス」→「ライブラリ」で **Google Drive API** を有効化
3. 「OAuth 同意画面」を設定
   - User Type: **外部** / 公開ステータス: **テスト**のまま
   - **テストユーザーに自分の Google アカウントを追加する**（忘れると認証が通らない）
4. 「認証情報」→「OAuth クライアント ID」→ 種類: **ウェブ アプリケーション**
5. **承認済みの JavaScript 生成元**に、PWA を置くサイトの**オリジンだけ**を登録する

   ```
   https://<ユーザー名>.github.io
   ```

   > ここはよく間違える箇所。**パスを含めてはいけない。**
   > `https://<ユーザー名>.github.io/DARUMA/` のように書くと登録できない。

6. 発行された**クライアント ID** を控える

> **「確認されていないアプリ」の警告について**
> 使用するスコープ `drive.readonly` は Google の制限付きスコープなので、
> テストモードでは初回に警告画面が出る。「詳細」→「（アプリ名）に移動」で進めれば使える。
> 個人利用なら審査を通す必要はない。

### 2. GitHub Pages で公開する

リポジトリの Settings → Pages → Source を **Deploy from a branch**、
ブランチを **main / (root)** にする。数分で下記が有効になる。

```
https://<ユーザー名>.github.io/DARUMA/
```

> GitHub Pages を無料で使うにはリポジトリが Public である必要がある。
> 公開されるのはコードだけで、要約データは含まれない。

Cloudflare Pages を使う場合は、このディレクトリを指定して `npx wrangler pages deploy .` でもよい。

### 3. スマホで開いて設定する

1. スマホの Chrome で PWA の URL を開く
2. 右上の ⚙ から**クライアント ID** を貼り付けて「保存」
3. 「Google と連携する」→ 同意（初回は上記の警告画面が出る）
4. 取り込みが終わったら、Chrome のメニューから**「ホーム画面に追加」**

以後はホーム画面のダルマから 1 タップで開ける。一度取り込めば**オフラインでも読める**。

## 使い方

| 操作 | 動作 |
|---|---|
| 検索 | タイトル・チャンネル・本文を全文検索（「ドンキ」で「ドン・キホーテ」に当たる） |
| チャンネルのチップ | 絞り込み |
| 項目をタップ | 詳細を開く。Android の戻るジェスチャで一覧へ戻る |
| `[m:ss]` をタップ | YouTube アプリがその時刻から開く |
| 📝 | ノート（PC でハイライトした箇所とメモ）を読む |
| ⟳ | Drive から取り込み直す |

ノートは PC の拡張機能で作る。ここでは読むだけ（要約と同じ役割分担）。

## 更新したときの注意

service worker がアプリシェルをキャッシュしているため、**デプロイ直後の 1 回目は古い画面が出る**。
裏で新しいものを取得しているので、**次に開いたときから新しくなる**。
すぐ反映したい場合は設定から「端末のキャッシュを消す」か、`sw.js` の `CACHE` の版番号を上げる。

## 構成

```
index.html            一覧 / 詳細 / 設定の3画面
app.js                OAuth・Drive取得・描画・IndexedDBキャッシュ
styles.css            スマホ優先。大画面では読み幅を制限
sw.js                 アプリシェルのみキャッシュ（認証とAPIは素通し）
manifest.webmanifest
icons/
```

要約を作る側（Chrome 拡張機能とローカルヘルパー）は別リポジトリ。
